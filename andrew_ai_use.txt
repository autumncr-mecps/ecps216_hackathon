---

## MPR121 Quick Refresher

The MPR121 works by continuously measuring capacitance on each of its 12 electrodes. It maintains two key data streams per electrode:

- **Baseline (BV):** A slow-moving average of the "ambient" capacitance on the pad. It adapts slowly to gradual environmental changes.
- **Filtered Data (FDC):** A faster, cleaner real-time capacitance reading.
- **Touch Detection:** A touch is flagged when **(Baseline − Filtered Data) ≥ Touch Threshold**. This difference is sometimes called the delta.

---

## The Core Problem: Water and Capacitance

Water (especially with dissolved minerals/salts outdoors) is **conductive and has a very high dielectric constant (~80 vs ~1 for air)**. This means:

- Water sitting on a pad **raises the capacitance** of that electrode significantly.
- This looks electrically similar to a finger touch, which can cause **false positives**.
- If the pad stays wet for a while, the **baseline will slowly drift upward** to track the new ambient capacitance level, which can then cause **false negatives** when a real touch occurs because the delta shrinks.

---

## Strategy: Using the Moisture Sensor Together

Since you're already planning to use a moisture sensor, you can build a **dual-mode detection system**. Here's how to think about it:

### 1. Moisture Sensor as a Mode Switch
Use the moisture sensor reading as a flag to switch between two detection configurations:

| Condition | Mode |
|---|---|
| Dry | Normal thresholds, standard baseline tracking |
| Wet | Adjusted thresholds, modified baseline behavior |

You essentially maintain two sets of MPR121 threshold register values and swap them based on the moisture sensor state.

---

### 2. MPR121 Threshold Tuning (Registers `0x41`–`0x5A`)

Each electrode has a **Touch Threshold (TH)** and **Release Threshold (RH)** register.

- **Dry condition:** Use your standard calibrated thresholds (typically TH ~12–16, RH ~6–10 for a typical setup, but you should calibrate for your pad geometry).
- **Wet condition:** You will need to **increase the touch threshold** to avoid false positives from water. The delta caused by water pooling tends to be more diffuse and gradual compared to a firm finger press. You'll need to experimentally measure the delta water causes vs. a real touch in your specific pad design and set TH above the water delta but below the touch delta.

---

### 3. Baseline Tracking Rate Control

The MPR121 has configurable baseline tracking filters via registers `0x2B`–`0x40`. Key parameters:

- **Maximum Half Delta (MHD), Noise Half Delta (NHD), Noise Count Limit (NCL), Filter Delay Count (FDL)** — these control how fast the baseline rises and falls.
- **In dry conditions:** Let the baseline track normally.
- **In wet conditions:** You may want to **slow down or pause baseline tracking** so that when water suddenly hits the pad, the baseline doesn't immediately chase the new value and mask a real touch. This keeps the baseline anchored to the dry reference longer, preserving sensitivity.

---

### 4. Debouncing and Temporal Filtering in Firmware

Rain and water splashes are **transient and noisy** — a real human touch is **sustained**. In your firmware:

- Require a touch to be **held for N consecutive samples** before registering it as valid (debounce). The MPR121 has a built-in debounce register (`0x5B`) for this — set the touch debounce count higher in wet mode.
- A rain droplet hitting the pad may spike the delta briefly, but a real touch will sustain it.

---

### 5. Multi-Electrode Consistency Check

If you have multiple electrodes, you can add a logic check:

- Rain/pooling water tends to affect **multiple electrodes simultaneously** (broad, diffuse capacitance increase).
- A real finger touch is typically **localized to 1–2 adjacent electrodes**.
- So if many electrodes fire at once → likely water, not a touch.

---

## Summary Flow

```
Read Moisture Sensor
      |
  [WET?] ──Yes──> Load WET thresholds (higher TH/RH)
      |            Slow baseline tracking
      |            Enable multi-electrode water filter
      |            Require higher debounce count
      |
  [DRY?] ──Yes──> Load DRY thresholds (normal TH/RH)
                   Normal baseline tracking
                   Standard debounce

Both paths → Read MPR121 delta per electrode
           → Apply debounce
           → Register valid touch
```

---

## Practical Tips

- **Calibrate indoors first** on dry pads to establish your baseline delta for a real touch.
- Then **simulate wet conditions** (mist the pad, let water pool) and measure the delta water alone creates — this tells you where to set your wet-mode threshold ceiling.
- Use **conformal coating or a thin dielectric overlay** on the pads if possible — this reduces the raw capacitance impact of water while still allowing touch detection, and is a common real-world solution for outdoor capacitive panels.
- Log the raw FDC and BV values during testing — the MPR121's I2C registers make this easy, and visualizing the data will help you tune thresholds much faster.

## What is Hysteresis in This Context?

Hysteresis means that the threshold to **enter** a state (touch detected) is **different and higher** than the threshold to **exit** that state (touch released). This creates a "dead band" between the two thresholds that prevents the sensor from rapidly toggling back and forth between touched and untouched states.

---

## MPR121's Built-In Hysteresis

The MPR121 directly supports this through its per-electrode threshold registers:

- **Touch Threshold (TH)** — the delta must **exceed** this to register a touch
- **Release Threshold (RH)** — the delta must **fall below** this to register a release

The gap between TH and RH **is** the hysteresis band. For example:

| Register | Dry Mode | Wet Mode |
|---|---|---|
| Touch Threshold (TH) | 12 | 20 |
| Release Threshold (RH) | 6 | 12 |
| Hysteresis Band | 6 | 8 |

In wet mode, you want a **wider hysteresis band** because the noise floor is higher due to water-induced capacitance fluctuations. A wider band means the sensor won't falsely release and re-trigger during a sustained touch while water is present.

---

## Why Hysteresis Helps in Your Scenario

There are a few specific reasons it is especially valuable for your outdoor project:

1. **Prevents chatter from water movement** — Water shifting or dripping across a pad causes the delta to fluctuate. Without hysteresis, the sensor could rapidly toggle touched/untouched. The dead band absorbs those small fluctuations.

2. **Stabilizes the touch-release boundary** — When a finger is pressing on a wet pad, the delta signal is noisier than on a dry pad. Hysteresis keeps the touch registered cleanly without flicker even if the signal wobbles around the threshold.

3. **Works well with your debounce logic** — Hysteresis and debounce are complementary. Hysteresis stabilizes the signal level, while debounce stabilizes the timing. Together they form a robust two-layer filter against false events.

---

## One Thing to Be Careful About

Setting the hysteresis band **too wide** in wet mode can hurt sensitivity — if TH is very high and RH is very low, you might miss light or partial touches, or the sensor might stay latched in a "touched" state longer than expected after the finger is removed. So you still need to calibrate these values experimentally against your specific pad geometry and expected real-world touch pressure.

---

## Practical Recommendation

- Start with a **TH:RH ratio of roughly 2:1** (e.g., TH=12, RH=6 dry / TH=22, RH=11 wet) as a baseline.
- Log your raw delta values during wet and dry testing and look for where the noise floor sits.
- Set RH comfortably above the noise floor, and TH above your worst-case water-only delta.
- Let the moisture sensor control which set of thresholds is loaded into the MPR121 registers at runtime.

In short — yes, hysteresis is not just good, it is essentially essential for a robust outdoor touch sensor implementation. The MPR121 is well-suited for it since the touch and release thresholds are independently configurable per electrode.

## It's Native to the MPR121

The MPR121 has dedicated threshold registers for every single one of its 12 electrodes. These are configured over I2C by writing to specific register addresses in the sensor's register map.

---

## Register Locations

Each electrode has two registers — one for touch, one for release:

| Electrode | Touch Threshold Register | Release Threshold Register |
|---|---|---|
| ELE0 | 0x41 | 0x42 |
| ELE1 | 0x43 | 0x44 |
| ELE2 | 0x45 | 0x46 |
| ELE3 | 0x47 | 0x48 |
| ELE4 | 0x49 | 0x4A |
| ELE5 | 0x4B | 0x4C |
| ELE6 | 0x4D | 0x4E |
| ELE7 | 0x4F | 0x50 |
| ELE8 | 0x51 | 0x52 |
| ELE9 | 0x53 | 0x54 |
| ELE10 | 0x55 | 0x56 |
| ELE11 | 0x57 | 0x58 |

Each register holds an 8-bit value (0–255), giving you fine-grained control per electrode.

---

## How to Set Them Over I2C

You write to these registers using a standard I2C write. Here is a simple example in C-style pseudocode:

```c
// The MPR121 must be in STOP mode before writing threshold registers
MPR121_write(0x41, 12);  // ELE0 Touch Threshold = 12
MPR121_write(0x42, 6);   // ELE0 Release Threshold = 6
```

Important: the MPR121 must be put into Stop Mode (write 0x00 to register 0x5E) before you can safely write to the threshold registers. After configuring, write your run configuration back to 0x5E to resume operation.

---

## How the Sensor Uses Them Automatically

Once set, the MPR121 hardware handles the rest entirely on its own:

1. It continuously computes the delta: Baseline − Filtered Data per electrode.
2. If delta ≥ TH → it sets that electrode's touch bit in the status registers (0x00–0x01).
3. The touch bit stays set until delta < RH → then it clears (release).

That gap between TH and RH is the hysteresis band, and it operates entirely in hardware with no extra firmware logic needed on your part.

---

## Key Rule to Always Follow

Always set TH > RH. If they are equal or RH is higher, there is no hysteresis band and the sensor can chatter. A good starting ratio is TH = 2× RH as mentioned before, then tune from there based on your measured delta values in wet and dry conditions.

## Range

Both `baseline_data` and `filtered_data` are **10-bit integers**, so their range is **0 to 1023**. They represent the capacitance measurement on each electrode in raw ADC counts — not volts, not farads, just a unitless capacitance-proportional integer.

In practice, in a typical resting environment, you'll see values somewhere in the **500–800 range**, depending on your electrode size, trace geometry, and surrounding materials. The exact resting value is not fixed — it varies by hardware design.

---

## What the Difference Looks Like

When the electrode is **untouched**, `baseline_data` and `filtered_data` track each other very closely — often within just a few counts:

```
baseline_data  = 650
filtered_data  = 648
delta          = 2   → no touch, below TH
```

When a **finger touches** the pad, capacitance increases, and `filtered_data` **drops** while `baseline_data` stays anchored (it only adapts slowly). This creates a growing positive delta:

```
baseline_data  = 650
filtered_data  = 625
delta          = 25  → touch detected if TH = 12
```

The thresholds you set (TH, RH) are **in these same delta count units**, which is why typical values like 12 or 20 make sense — they represent a small but meaningful number of ADC counts.

---

## Are They Before or After Hysteresis?

They are **completely raw — before any hysteresis processing**. The pipeline looks like this:

```
Electrode Capacitance
        ↓
  filtered_data  (10-bit raw ADC reading, real-time)
        ↓
  baseline_data  (10-bit slow-moving average, adapts over time)
        ↓
  delta = baseline_data − filtered_data  (computed internally)
        ↓
  Compare delta to TH / RH thresholds  ← hysteresis lives HERE
        ↓
  Touch status bit set or cleared in registers 0x00–0x01
```

So when you read `baseline_data` and `filtered_data` over I2C, you are reading the raw capacitance values **upstream of all threshold and hysteresis logic**. This is actually very useful for your project — you can log these raw values during testing to observe exactly what water vs. a real touch looks like numerically, which directly informs what TH and RH values you should configure for your wet and dry modes.

AI: This was actually covered earlier in our conversation, but here is a clean and complete explanation:

---

## The Core Mechanic

The MPR121 continuously computes a **delta** for each electrode:

```
delta = baseline_data − filtered_data
```

When nothing is touching the pad, filtered_data closely tracks baseline_data, so delta stays near zero. When a touch occurs, filtered_data drops while baseline stays anchored, so delta grows positive.

---

## How TH and RH Are Applied

The sensor compares that delta against your configured thresholds every measurement cycle:

- If **delta ≥ TH** → touch bit is **set** (touch detected)
- If **delta < RH** → touch bit is **cleared** (touch released)
- If **RH ≤ delta < TH** → touch bit **holds its current state** — this is the hysteresis dead band

So the state machine per electrode looks like:

```
[UNTOUCHED]
     |
     | delta rises to ≥ TH
     ↓
[TOUCHED]
     |
     | delta falls to < RH
     ↓
[UNTOUCHED]
```

---

## Why the Dead Band Matters

If TH = 12 and RH = 6, the dead band is the range 6–11. Once a touch is registered, the delta has to fall all the way below 6 before a release fires — it cannot accidentally un-register at delta = 10 due to minor signal noise or a shifting wet surface.

---

## Key Takeaway

The thresholds operate entirely on the **delta**, not on the raw baseline or filtered values directly. Hysteresis is the natural result of TH and RH being different values — the sensor does all of this in hardware automatically once you write those register values.

## Using `atexit` — Runs on Normal Program Exit

```python
import atexit

def cleanup():
    print("Cleaning up before exit!")

atexit.register(cleanup)
```

`atexit` runs your function when the program exits normally — such as reaching the end of the script or calling `sys.exit()`.

---

## Using `signal` — Runs on SIGINT (Ctrl+C)

```python
import signal
import sys

def handle_sigint(signum, frame):
    print("SIGINT received! Cleaning up...")
    sys.exit(0)

signal.signal(signal.SIGINT, handle_sigint)
```

`signal.signal()` registers a handler that fires specifically when your program receives a SIGINT, such as the user pressing Ctrl+C.

---

## Combining Both

If you want cleanup to run on **both** normal exit and Ctrl+C, use them together:

```python
import atexit
import signal
import sys

def cleanup():
    print("Cleaning up!")

def handle_sigint(signum, frame):
    sys.exit(0)  # This triggers atexit

atexit.register(cleanup)
signal.signal(signal.SIGINT, handle_sigint)
```

The key trick here is that calling `sys.exit()` inside the SIGINT handler causes `atexit` registered functions to run, so you only need to define your cleanup logic once.
